## Features

- **The config knows the mode.** `bongo dev` sets `NODE_ENV` to `development`, and `bongo build` sets it to `production`, before the config loads. A value that you set stays. See [Dev or build](/config/#dev-or-build). ([#81](https://github.com/lukeed/bongo/pull/81))
- **Scripts know the mode.** Scripts get `process.env.NODE_ENV`, `import.meta.env.DEV`, and `import.meta.env.PROD`. In `bongo dev`, packages resolve with the `development` condition. See [Script values](/config/#script-values). ([#82](https://github.com/lukeed/bongo/pull/82))
- **`$build.define`** replaces your own names in scripts. See [Your own values](/config/#your-own-values). ([#82](https://github.com/lukeed/bongo/pull/82))
- **`bongo/env`** types `import.meta.env`. Add it to the `types` of your `tsconfig.json`. ([#82](https://github.com/lukeed/bongo/pull/82))
- **tsconfig `paths`** aliases work in the config, data modules, and partials. ([#84](https://github.com/lukeed/bongo/pull/84))

## Fixes

- bongo no longer reads a `tsconfig.json` above the project folder, which can belong to another project. See [Which tsconfig.json](/typescript/#which-tsconfigjson). ([#83](https://github.com/lukeed/bongo/pull/83))
- A build through a symlinked project path writes the same scripts as a build through the real path. ([#85](https://github.com/lukeed/bongo/pull/85))
- `bongo/client` ships its types. Before, its functions had no types outside this repository. ([#86](https://github.com/lukeed/bongo/pull/86))
- A new site from `create-bongo` passes `tsc`. The template installs `@types/node`, sets `"types": ["bongo/env", "node"]`, and targets ES2024. ([#82](https://github.com/lukeed/bongo/pull/82), [#86](https://github.com/lukeed/bongo/pull/86))

## Performance

- `$assets.render` is about 9× faster on a cold cache. resvg no longer loads every system font for each image, and it draws off the main thread. ([#79](https://github.com/lukeed/bongo/pull/79))
