## Features

- **`$build.outdir`** and **`--outdir`** (`-o`) name the output folder; the flag wins over the config. A config that fails to load empties only the `--outdir` folder, or the folder of the last good build. See [Output folder](/cli/#output-folder). ([3c6a771](https://github.com/lukeed/bongo/commit/3c6a771))
- **`$assets.classes()`** gives a template the class names of a CSS module, as its stylesheet ships them. The module compiles once for both. See [CSS modules](/css/#css-modules). ([#88](https://github.com/lukeed/bongo/pull/88))
- **`$build.trailingSlash: false`** makes each page an `.html` file of its path, at a URL with no trailing slash. See [Without trailing slashes](/content/#without-trailing-slashes). ([#87](https://github.com/lukeed/bongo/pull/87))
- **`bongo dev` redirects a page URL with the other trailing slash** to the path of its file, as a host does. See [Trailing slashes](/dev-server/#trailing-slashes). ([#87](https://github.com/lukeed/bongo/pull/87))

## Fixes

- The client leaves `history.pushState()` and `history.replaceState()` to the page. Before, it fetched the URL as a page, so a widget that wrote its state into the URL lost it. Back and forward within one page no longer fetch it again. See [Opt out](/client-runtime/#opt-out). ([#90](https://github.com/lukeed/bongo/pull/90))
- A script import that does not resolve fails the build, and names the import, the file, and the line. Before, the script shipped the import as written, and failed in the browser. See [Imports](/special-elements/#imports). ([#88](https://github.com/lukeed/bongo/pull/88))
- A regex with a quote or a backtick, such as `` /`/g ``, no longer breaks the next template tag. tempura is now 1.0.1. ([#89](https://github.com/lukeed/bongo/pull/89))
- A class of a CSS module that composes a class that composes another gets the names of all of them. ([#88](https://github.com/lukeed/bongo/pull/88))
- The file name alone decides if a stylesheet is a CSS module, so `<bongo:style>` takes no `global`. With `global`, a `.module.css` file shipped its classes as written, while `$assets.classes()` gave hashed names. ([#88](https://github.com/lukeed/bongo/pull/88))
- Under Node, code that calls a Bun API fails with a hint to run bongo with Bun. A partial that calls such code is no longer told to add `{{#expect Bun}}`. See [Run with Bun](/cli/#run-with-bun). ([357b79a](https://github.com/lukeed/bongo/commit/357b79a))
- The Markdown copy of a dotted path, such as `/releases/v1.1.0`, is `v1.1.0.md`, not `v1.1.md`, and the client takes a link to such a page. ([#87](https://github.com/lukeed/bongo/pull/87))
- A missing asset no longer reads `asset!, rendering …`. ([#88](https://github.com/lukeed/bongo/pull/88))

## Performance

- A build with no change no longer renders every page that links a CSS module. On 10,000 pages, such a build takes 0.24 s, not 2.37 s. ([#88](https://github.com/lukeed/bongo/pull/88))

## Docs

- CSS: `@import`, composing a class of another CSS module, and why a script cannot import a stylesheet. See [`@import`](/css/#import) and [Stylesheets and scripts](/css/#stylesheets-and-scripts). ([#88](https://github.com/lukeed/bongo/pull/88))
- [Run with Bun](/cli/#run-with-bun) covers your own code that calls a Bun API, not only images. ([357b79a](https://github.com/lukeed/bongo/commit/357b79a))
